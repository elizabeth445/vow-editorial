# Vow Editorial — правила проекта

## Проект и проверки

- Общайся на русском; сайт остаётся на украинском. React, TypeScript, Vite, GSAP, Motion и Lenis. Данные свадьбы и гостей — src/data/weddingConfig.ts. Сохраняй персональные ссылки, конверт, календарь, RSVP, localStorage и reduced motion; backend не подключать без запроса.
- Менеджер пакетов — pnpm, сохраняй pnpm-lock.yaml. Установка: pnpm install --frozen-lockfile. Если runtime отсутствует: source ~/.codex/bin/frontend-env.sh.
- Перед публикацией запускай pnpm run verify: lint, TypeScript, Playwright и production build. Просматривай сайт и мобильные снимки на 320, 390, 768, 1024 и 1440 px; проверяй анимации, формы, навигацию и консоль. Vercel: Vite, build pnpm run build, output dist. Деплой требует отдельного запроса.
- Перед коммитом проверяй status, diff и staged diff; убирай только доказанно ненужное. Не публикуй node_modules, dist, скриншоты/отчёты тестов, HTML-экспорт, кэши и .env*. Сохраняй рабочие изображения, документацию, лицензии, lock-файл и эталонные снимки тестов. Проверяй кандидатов на секреты без вывода значений.

## Постоянное разрешение на commit и push

Пользователь явно разрешил следующий цикл для каждой успешно завершённой задачи изменения этого сайта: локальная правка → проверки → понятный коммит → немедленная отправка → проверка удалённого SHA. Дополнительное подтверждение обычного commit/push не требуется. Это проектное разрешение имеет приоритет над общим правилом ожидать отдельную команду на push; к другим проектам оно не относится.

- Единственное разрешённое назначение: https://github.com/elizabeth445/vow-editorial.git (origin), ветка main. Перед каждой отправкой проверяй remote и ветку, получай свежий origin/main и сохраняй существующую историю. Включай только предназначенные изменения, не коммить чужую работу.
- Используй локальный Git при рабочей авторизации или подключённый GitHub-плагин. При отправке через плагин создавай коммит поверх фактического main и обновляй ref с force=false и expected_sha; затем синхронизируй локальный Git и сверяй SHA и дерево файлов.
- Запрещены force push, переписывание истории, разрушительные Git-команды и публикация секретов. При конфликте, неожиданном изменении main, ошибке Git или неуспешной проверке не перезаписывай удалённые изменения и не обходи ошибку: сообщи проблему.
- Не настраивай автодеплой и не выполняй deploy по этому разрешению. Не сохраняй токены/пароли в коде, remote URL или файлах проекта.
- После задачи кратко сообщай по-русски: что изменено, результаты проверок, успешность отправки и SHA коммита. Проверяй фактический origin/main, а не только сообщение инструмента.
